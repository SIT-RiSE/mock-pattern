# mock-pattern v2

v2 用 CloneDeMocker-v2 的检测（`CloneDeMocker-v2/DETECTION`）提取 mock 和 MCI，在此之上重新判定 L0/L1/L2，并统计升级（L0→L1/L2，即消除 mock 克隆）的理论削减量。不编译被测项目、不解析依赖、不调用 LLM。旧版代码（`edu.mock.mockpattern.*`，论文现有数据）保持不变，v2 位于 `edu.mock.mockpattern.v2`。

## 与旧版的区别

| 问题 | 旧版 | v2 |
|---|---|---|
| mock 创建识别 | 方法名为 `mock`/`spy` 即可 | CloneDeMocker：symbol resolution 确认 `org.mockito.Mockito.mock`，失败时要求静态导入或 `Mockito.` 限定；排除 `mockStatic`/`mockConstruction` |
| 嵌套语句 | 只扫方法体顶层语句，`try`/`for`/`if`/lambda 内的 mock 漏检 | 递归扫描所有语句 |
| spy | 当作 mock | 排除 |
| 无创建语句的变量 | 只要出现在 `when`/`verify` 就算 mock | 若由 helper 返回的 mock 初始化，合并回该 mock；否则排除 |
| 测试方法识别 | 方法名含 "test" 或注解名含 "test" | `@Test`/`@ParameterizedTest`/`@RepeatedTest`/`@TestFactory`/`@TestTemplate` 等注解；JUnit3 为继承 `*TestCase` 的 `public void testXxx()` |
| helper 是否共享 | 方法名含 mock/init/create/setup/... | 调用图：被 ≥2 个测试调用，或被 setup/字段初始化/构造器调用 |
| setup 中的局部变量 mock | 一律 L0 | 创建位置为 setup，算共享 |
| 升级候选 | Apriori 按类型在全项目聚簇（可跨包） | CloneDeMocker 的 MCI（同类型、同包） |

## 位置与分级

每条 mock 语句所在方法被归为：`FIELD`、`SETUP`（`@Before*`、JUnit3 `setUp`）、`TEST`、`SHARED_HELPER`、`SINGLE_HELPER`（只被 1 个测试调用）、`UNREACHED_HELPER`（未被任何测试或 setup 调用）、`TEARDOWN`、`UNKNOWN`。

- 创建 C 共享：创建语句位于 `FIELD`、`SETUP`、`SHARED_HELPER`。
- stub 共享：位于 `SETUP`、`SHARED_HELPER`；其余为本地。
- L0：C 本地且无共享 stub。
- L1：C 共享且无本地 stub（含无 stub）。
- L2：C 共享且有本地 stub。
- C 本地但存在共享 stub 的情况记为 L2，并标记 `local-creation-shared-stub`。

## 升级统计（summary.json）

- `mciCount`、`mciMocks`、`mciL0Mocks`：进入 MCI 的 mock 数及其中的 L0。
- `mocksReduced`：Σ(每个 MCI 的 mock 数 − 1)。
- `stubsReduced`（抽象口径）：MCI 中与核心 stub 抽象形式相同的本地 stub 数 − 核心 stub 数。
- `stubsReducedExact`（精确口径）：只合并 mock 变量名替换后代码完全相同的 stub（每个核心 stub 取出现最多的写法）。抽象口径把 `thenReturn(false)` 与 `thenReturn(true)` 视为同一条，会高估；真实重构的结果通常落在两个口径之间。

## 运行

先在 `CloneDeMocker-v2/DETECTION` 执行 `mvn install -DskipTests`，然后：

```bash
# 单个项目
python scripts/run_projects.py --work D:/Java_projects/mock-pattern-v2 --only Dubbo
# 全部 260 个项目（中断后重跑即续跑）
python scripts/run_projects.py --work D:/Java_projects/mock-pattern-v2
```

每个项目输出 `results/<project>/{mock-objects,excluded,mci,summary,run}.json`，汇总在 `<work>/summary.csv`（含每个项目的 commit）。
